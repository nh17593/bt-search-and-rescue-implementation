BT Playground: Scout, Medic, Guard

These trees use the actual implementation at repository commit f9fa69bc91c57f80004c0d76f143128735d9a0b0. The repository itself was not modified. The source is index.html.

Choose either method: import both supplied JSON files, or build each tree using the numbered parent/child tables below. Every Custom Process expression is included below and in its own JavaScript file; paste the code into that node's Expression field. Do not execute those snippets in the browser console.

Setup and import

  1. Extract the ZIP. Keep your current work exported separately if you need it.
  2. Load Operation Quick Rescue, then open Import and select both bt_tree.json and bt_sim_config.json. Apply the staged imports. The tree JSON contains all three BT Library entries and their robot assignments; the config contains the scenario and settings.
  3. Check R1 → R1 Scout, R2 → R2 Medic, R3 → R3 Guard. Select the R1 Scout tab before resetting. Use Fit to see the whole canvas.
  4. Set the top Robot speed slider to 10. The imported setting controls the engine, but this version does not refresh that slider's displayed value.
  5. Confirm scout sensor range 200, communication range 300 for every robot, global FOV 360°, and global battery drain 0.7%/tick. R3's Obstacle? nodes explicitly use range 42 and FOV 360°.
  6. Click the simulator's Reset before the first Step/Run. Reset initializes the delayed appearances: W4 at 15, V2 at 20. Simply loading this scene does not initialize their spawnAtTick fields.
  7. Run all three together. Pause at 10, 15, 20, 35, and 100. The Explain pane contains all robots' traces.
Required scene correction: the stock rescue scene has an SZ waypoint but an empty collectionZones list. Drop Off outside a collection zone re-creates an uncollected package. The config adds a collection rectangle at x=60, y=45, width=40, height=40 around SZ. Its two valid drop targets are North=(95,50) and East=(95,80). The original five named waypoints, four walls, package positions, and appearance/deadline times are preserved. For a manual build, use the Collection Zone tool to draw this rectangle and verify its position in the object inspector.

Keep Scout displayed during the run. This version recreates node IDs when changing BT tabs, which can invalidate the ID-indexed memory of running tasks. To inspect a different robot, use its Explain entries rather than switching the tree tab mid-run.

How to build from the tables

Start with the Root row. Add each numbered node, apply its exact label and settings, and connect it to the numbered parent. Children are listed in left-to-right priority order. The playground sorts siblings by their horizontal canvas position, so arrange them left to right in that order. Decorators take exactly one child. Composite nodes can have several.

All blackboard state is local. Do not prefix a BB key with /, select global scope, or write GLOBAL_PARAMS. Slashes on topic names are correct. Custom Process nodes below read/write only the executing robot's local BB and bind parameters of nodes in that robot's current tree. R1 accesses package attributes only after a physical range/FOV and hidden/collected check; R2 gets discoveries exclusively from Read Topic.

For Navigate To, a coordinate such as 295,155 goes entirely in Target / X; leave Y blank. Unless a row says otherwise, use Config Params arrivalDist=6, look=28, N=72, avoid=1.2. R2's Approach nodes use arrivalDist=16 because Pick Up's physical pickup radius is 18. Guard navigation uses arrivalDist=2.

Publish Topic's Value field accepts literals or a local ~parameter, but not an evaluated bb.key expression. The Scout preparation node sets the Publish node's own payload parameter; Value=~payload then sends a JSON string containing the discovered IDs and coordinates. Medic's preparation node similarly binds received coordinates to the appropriate Navigate To parameters. These are explicit node-parameter updates; no global BB is used.

// Perception: inspect only physically present packages within R1's sensor/FOV.
bb.found = bb.found || {};
for (const p of ENV.packages) {
  if (p.hidden || p.collected) continue;
  if (!inFOVfull(rob, p.x, p.y, getRobSensor(rob), FOV_DEG)) continue;
  bb.found[p.label] = {id:p.label,x:p.x,y:p.y,

if (pub) { pub.params = pub.params || {}; pub.params.payload = bb.report; }
